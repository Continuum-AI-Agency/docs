Use [the quickstart](/forge/agents) first. Every call uses the active brand and normal [MCP sign-in and access rules](/mcp/reference).

Checked 2026-10-29: **17 query actions** and **18 management actions**. These are contract entries, not a promise that every source format or client can execute them.

Fetch only the action you need with `help_describe {tool, action}`. Some connectors advertise an older action enum. If your client cannot represent an action, refresh its tool discovery or use a client that exposes the current contract; do not silently substitute another action.

The [operation index](/forge/agent-manifest.txt) supplies compact routing facts. Full inputs stay in runtime discovery. Fields marked required below include action-specific validator requirements that a flat JSON schema may omit. Successful Forge results use `{status: "ok", action, result}`; read the fields below inside `result`.

<Warning>`render_preview` is a preflight, not a pixel render. Inspect saved delivery settings: omitted settings inherit. Show the person the rows, destinations and any spend before confirming. Use the exact `confirmationToken` returned by the Forge action.</Warning>

| Conditions | The service reloads the current scene at submission; immutable scene-version execution is not guaranteed. Recheck scenes before confirming; if it changed, fill/review again. |
| Returns | assetId, values, jobs[{outputId, jobId}], next |
| Role | Operator or higher |
| Side effects | Queues one scene render per output into the Library. |
| Potential spend | Yes: scene rendering can spend provider budget; this response does not supply a price estimate. |
| Confirmation | Show filled values and outputs, explain potential spend (estimate may be unavailable), wait for a yes, then pass the exact scene_fill token. |
| Completion | Scene jobs use the template’s scene history in Forge and the Library; they are not Forge render-set batches. |
| Retry | Token is single-use; after an uncertain response inspect history before another fill/render. |
| Errors | VALIDATION_ERROR: expired_confirmation; CONFLICT: confirmation_spent |

Schema: `help_describe {"tool":"forge_manage","action":"scene_render"}`.


## Recover from a refusal

- **Revision conflict:** re-read the set or template head, reconcile the intended change, and preview again. A set's numeric `expectedRevision` is different from a template revision UUID.
- **Ambiguous template key:** select the discovered `bindingId`; do not guess a workspace.
- **Insufficient role:** preserve `needs_role` or `PERMISSION_DENIED` and request the appropriate brand role. `final=true` and template publication need Admin or Owner.
- **Expired or spent token:** inspect existing jobs first if submission may have succeeded. Otherwise preview/fill again and obtain a new yes; never turn an uncertain response into an automatic second render.
- **Missing fonts or another overridable refusal:** pass a flag only when `details.overrides` names it and the person explicitly accepts that specific problem. Other refusals remain blocking.
- **Partial or failed batch:** inspect each job. `done=true` means settled, including failures; it does not mean every output succeeded. Preserve job IDs and reasons.
- **Scene jobs:** use the template's scene history in Forge and the Library. Do not pass a scene job ID to the render-set job API without a supported contract.

No Forge webhook subscription or cancellation action is established by this catalog. Your host application starts MCP calls and retains their identifiers.

## Example call sequences

These are sequential MCP `tools/call` parameters, not an executable batch. UUIDs, tokens, template and variable keys are illustrative: substitute the exact discovered values. Populate required template fields before preflight. Obtain permission for automatic preparation/spend before completing a source upload or saving a revision; pause for the person's yes before render confirmation. A render price estimate may be unavailable.

Keep each returned identity for the next call. After publication, rediscover the matching template key/binding and use the published revision UUID. For scenes, recheck the version before confirming; the service still reloads the current scene. Follow the individual action's conditions above.
