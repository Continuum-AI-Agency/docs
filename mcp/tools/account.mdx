### brand_knowledge

Reads and searches your brand book and knowledge base, checks copy against your voice, and adds, updates, or archives source material.

| Contract | Behavior |
| --- | --- |
| Changes things | Yes |
| Listed in your assistant | Always. |
| Role | Any brand member |

| Confirmation | Writes preview first and return a `confirm_token` with `expires_at`. Confirm with that token after the person says yes. |
| Completion | Returns right away. Longer work continues as a job; read the id in the result. |
| Retry | Retry with the same `idempotency_key` to avoid duplicates. |

**What the server tells your assistant:**

> Read and search everything Continuum knows about the active brand — the brand book, brand guidelines, the uploaded-document knowledge base, onboarding intake, and the structured profile. Use it to ground yourself in the brand before writing content or analyzing performance. action=overview lists what is available (readiness, guideline purposes, document counts by category, onboarding status, profile sections). Read `brand_book.alignment_claimable` before you write anything: when it is false this brand has no verifiable brand book, and you MUST NOT describe your output as "aligned to the brand book" — say what you actually grounded it in and surface the returned `warning`. `documents.unclassified` counts documents still filed as misc; while it equals the total, the `categories` search filter cannot match anything. action=search runs semantic search over the uploaded knowledge base (`query`; optional `categories` filter such as brand_guidelines/creative_strategy/audience_persona/product_info; add `sources` — any of ['documents','guidelines','brand_report'] — to also search brand guideline tags and brand-report vectors). action=read fetches a whole artifact via `source`: brand_book (DNA + readiness; add `full:true` for the full brand.md), guidelines (structured colors/typography/verbal identity; optional `purpose`), onboarding (intake answers), or profile (voice/pmf/audience/persona + context; optional `section`). action=validate checks `copy` for a `platform` against the brand's voice rules. WRITES (operator role): action=add_text stores agent-authored markdown as a document (`name`, `text`); action=add_url ingests an https document by URL (`name`, `url`; a Google Drive/Docs/Slides link works when shared as 'Anyone with the link'). Both accept `category` and `retention` — omit `category` and the document is classified from its name and content (the result reports what it was filed as); retention=ephemeral scopes it to THIS session and expires it in 14 days. action=add_file accepts a small (up to 5 MiB) PDF, DOCX, PPTX, XLSX, CSV, text or supported image as padded file_base64 with file_name and mime_type; it returns a documentId for Forge drafts. For a larger file (up to 50 MB, e.g. a PDF brand book) when you can run a shell: action=upload_url (`file_name`, `mime_type`) returns a put_url and curl line; PUT the bytes, then action=upload_finalize (`upload_path`, optional `name`/`category`) ingests it like a web upload. action=update renames or re-categorizes (`document_id`, `name`, `category`; pass `expected_updated_at` to avoid clobbering a concurrent edit). action=archive takes a document down and is two-phase: call it once for a preview + confirm_token, then again with mode='confirm'. action=restore undoes an archive. action=save_permanent promotes an ephemeral document to brand-wide permanent knowledge. action=document_status polls ingest progress after a write. Returns a structured needs_* result if no brand is selected.

### agent_ask

Asks [Jaina](/performance/jaina) or the [Organic agent](/organic/agent) a question. Runs as a job.

| Contract | Behavior |

**What the server tells your assistant:**

> Send a free-form question to a Continuum agent, routed by the required `target`. For raw metric/number lookups (e.g. 'get IG metrics for @account', spend/ROAS/impressions for an account or campaign), call analytics_query directly — agent_ask is for interpretation, narrative reports, and multi-step analysis, not fetching a metric. Use when the question fits one of: target=jaina for performance/paid analytics, reporting, ROAS/spend/campaign/pacing questions; target=organic for social strategy, captions, content ideas, or organic post/account questions. Do NOT guess a target for a query about the other domain — the server validates `query` against `target` with a deterministic classifier and returns status=needs_correction (with suggested_target) instead of silently running the wrong agent on a confident mismatch; ambiguous or mixed-intent queries proceed as requested. Returns immediately with result.\{ job_id, sessionId, poll_with \} — poll jobs_status for the answer. The completed job result carries status: 'completed' when the run wrote a draft/plan, or status: 'needs_followup' when it produced text only; on needs_followup, send the next instruction with the SAME result.sessionId to continue the thread instead of restarting it. When target=organic ends holding an approval-gated plan the job result also carries \{ plan_id, pending_approval_token, placements \} — commit that plan by calling organic_calendar_approve with those three (24h token, single use). Returns a structured needs_* result if the brand/role prerequisites are missing.
