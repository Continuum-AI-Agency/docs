### `planner_manage`

Reads and proposes a week of posts, approves it, reschedules and copies posts, and attaches media.

**Good to know:**

- `propose_week` runs as a job. `proposal_status` returns its `plan_id` and a `pending_approval_token` that lasts 24 hours.
- `approve_week` commits the whole week in one step and is safe to repeat. The `job_id` from `propose_week` can stand in for `plan_id`, `pending_approval_token`, and `placements`.

| Contract | Behavior |
| --- | --- |
| Changes things | Yes |
| Listed in your assistant | Always. |
| Role | Viewer or higher for `get_week`, `proposal_status`, and `operation_status`. Operator or higher for every other action. |
| Needs | An active brand. Connection: The one for what you act on: Instagram. |
| Confirmation | Writes preview first and return a `confirm_token` with `expires_at`. Confirm with that token after the person says yes. |
| Completion | Returns right away. Longer work continues as a job; read the id in the result. |
| Retry | Each `confirm_token` works once. Preview again to retry. |

### `content_create`

Drafts, approves, and publishes posts, and deletes drafts.

**Good to know:**

- `approve` returns the `confirm_token` that `publish` needs. Publish only after the person says yes.
- `platform` accepts every network the schema knows. Publishing is live on Instagram; [Publishing](/organic/publishing) has the status of the others, and X isn’t offered for publishing.
- `realize` (generating the creative) and `delete` are two-phase. A `realize` preview returns `approve_with`: send `approve_with.input` back as the next `realize` call to confirm exactly what was previewed. `delete` returns a `confirm_token` instead.
- `reference_assets` (up to 8 Library images) and `unsplash_photos` (up to 4) steer image generation, on `draft` and `realize` only.
- `draft` needs a `prompt` unless you pass `generate: false`; then it saves the `caption` and `hashtags` you pass word for word.

| Contract | Behavior |
| --- | --- |
| Changes things | Yes |
| Listed in your assistant | Always. |
| Role | Viewer or higher for `list`. Operator or higher for every other action. |
| Needs | An active brand. Connection: The connection for the post’s `platform`. |
| Confirmation | The person approves the pending change; the approval is the yes. |
| Completion | Returns right away. Longer work continues as a job; read the id in the result. |
| Retry | Retry with the same `idempotency_key` to avoid duplicates. |

**Actions** (`action`):
