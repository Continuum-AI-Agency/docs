Reads and proposes a week of posts, approves it, reschedules and copies posts, and attaches media.

**What the server tells your assistant:**

> Plan and reshape the content calendar — the Planner as one outcome. action=get_week returns the exact week the planner renders (day, time-of-day, status, origin per draft) — pass any day inside the week as week_start, or omit it for the current week. It also answers when the week itself is empty: `unscheduled` carries drafts with no day at all and `overdue` the 50 most recent still-actionable drafts whose day has already passed (`scheduled_in_past` flags them per draft). Days and times are rendered in the brand timezone, reported as time_zone + utc_offset; pass `timezone` to override. action=propose_week plans a week (async, returns a poll handle); action=proposal_status polls it and surfaces plan_id + the 24h pending_approval_token; action=approve_week commits the proposal in ONE transaction at stable ids (replay-safe). action=reschedule moves one draft to a day keeping its time-of-day; action=reschedule_many moves up to 50 in one transaction; action=copy duplicates a day (or named drafts) onto another day at deterministic ids; action=attach_media appends to an existing carousel by default; set replace=true to replace its media. action=bulk_transition changes lifecycle status in bulk (to_status='scheduled' or 'failed' is two-phase: mode='preview' returns a confirm_token, mode='confirm' applies it). Every batch returns operation_id, status (completed\|partial\|failed), applied/failed/unchanged, rollback_state and next_actions; pick atomicity='all_or_nothing' (nothing is written unless every item validates) or 'best_effort' (itemized, applied items are kept). action=operation_status re-reads any operation_id. Deleting a draft stays with content_create action=delete — a bulk hard delete has no restore.

**What the server tells your assistant:**

> Create and ship organic content (the full write lifecycle) to the platforms with a real publisher. action=draft (requires `platform`) returns a draftId for a caption/plan post (generate=false mints a bare stub, and with generate=false you may pass `caption` / `hashtags` to store copy that was already written and approved — it is saved verbatim, nothing is regenerated); action=extend edits a draft — pass `updates` for a structured field change (scheduled_date/slot_data/content_json, trial_reel to publish an Instagram reel to non-followers first, or status back to draft/placeholder; approved/scheduled/published/failed are owned by the approve+publish actions) OR `prompt` for a natural-language rewrite (e.g. 'rewrite the caption in Mexican Spanish'), which runs the organic agent in place and returns a poll handle; action=realize generates the creative — two-phase like the other spending writes: call it with the draftId alone to get back the draft's `preview_revision` plus the storyboard frames it covers (state=awaiting_preview_approval), then call it again with that `preview_revision` to approve those frames and generate (state=generating); a draft with no storyboard yet gets one built first (state=previewing). For draft or realize, `reference_assets` accepts up to 8 pinned `{asset_id,version_id}` Library images returned by library_manage and feeds those exact versions to image generation; `unsplash_photos` adds up to 4 `{photo_id}` from unsplash_search as references the same way (8 images in total). action=approve issues a publish confirm_token; action=publish ships it with that token; action=delete permanently removes a draft — two-phase like publish: mode='preview' returns a confirm_token, mode='confirm' with that token and an idempotency_key performs the irreversible hard delete (a no-op if the draft is already gone). Re-read drafts with organic_draft_get / organic_draft_list (the poll/read targets). Returns a structured needs_* result if prerequisites are missing.

**What the server tells your assistant:**

> List organic calendar drafts for the active brand, each carrying its publish verdict. Rows are lean by design — id, status, scheduled date, platform, format, a truncated caption_preview and `publishability`; read a draft's full content with organic_draft_get. `publishability` says whether it can publish, every blocker if not, the resolved account/platform/format, and whether that platform's integration is connected or needs re-auth. Supports cursor-based pagination (default 5 per page), status filtering, and date range filtering on scheduled_date; page with `next_cursor`.

**What the server tells your assistant:**

> Fetch a single organic calendar draft by ID for the active brand — the full row including content_json (its media URLs re-signed at read time), plus the same `publishability` verdict organic_draft_list carries (can it publish, every blocker if not, resolved account/platform/format, integration state). The row carries four state axes and they are ORTHOGONAL, not ranked: `status` is the lifecycle a human drives (draft→approved→scheduled→published), `media_stage` is the enrichment ladder (text_only→storyboard_ready→realizing→realized), and `mediaStatus` / `blueprintReady` inside content_json are the generator's own per-run flags. An approved draft whose media is still pending is a legal state, not a contradiction — `publishability` is the only field that decides whether it can post. The brand_id filter is enforced server-side to prevent cross-brand access.
