### paid_manage

Reads your campaign structure; creates paused campaigns, ad sets, and ads; updates or pauses them; builds audiences and lookalikes; and keeps an audit log of every write.

| Contract | Behavior |
| --- | --- |
| Changes things | Yes |
| Listed in your assistant | Always. |
| Role | Any brand member |
| Needs | An active brand |
| Confirmation | Writes preview first and return a `confirm_token` with `expires_at`. Confirm with that token after the person says yes. |
| Completion | Returns the result in the same call. |
| Retry | Each `confirm_token` works once. Preview again to retry. |
| Rate limit | 60 calls per 1 hour per brand. See [Limits](/mcp/reference#limits). |

**What the server tells your assistant:**

> Manage paid media on Meta ads (and Google Ads via action=google_ads). Read: hierarchy (campaigns/ad sets/ads with budgets, targeting, deleted ads on request), activity (audit log of every paid write: who, request, result). Write: create_campaign (optionally with ad sets and ads in one go), create_adset (radius/geo, age, gender, interests, audiences, placements, optimization goal, destination incl. WhatsApp, budget, schedule), create_ad, upload_media, update_entity (budget, bid, bid strategy, optimization goal, name, schedule, targeting, placements, status PAUSED/ACTIVE/ARCHIVED), update_ad_copy, duplicate, create_audience, create_lookalike, create_customer_list_audience, delete_audience, send_conversions (Conversions API, incl. offline), manage_rules (Meta automated rules), google_ads, guardrails (spend caps). Campaigns, ad sets, ads and copies are created PAUSED. Every write is two-phase: params.mode='preview' returns a diff + confirm_token (10 min), then mode='confirm'. Activating (incl. creating an ENABLED Meta rule), raising a budget past the brand's guardrails (default +30%), or a brand with an approval chain needs an admin to call mcp_approval_grant on the token. action=batch previews many writes under ONE confirm_token. Each write receipt returns `undo` — the paid_manage call that reverses it, or null + the reason when Meta cannot (sent conversions, archive). Organic-post boost is not supported. Full per-action schema: help_describe \{ tool: "paid_manage", action \}.

### optimizer_manage

Approves or rejects recommendations and manages portfolios.

| Contract | Behavior |
| --- | --- |
| Changes things | Yes |
| Listed in your assistant | Always. |
| Role | Any brand member |
| Needs | An active brand |
| Confirmation | Writes preview first and return a `confirm_token` with `expires_at`. Confirm with that token after the person says yes. |
| Completion | Returns the result in the same call. |
| Retry | Not idempotent. Check the current state before retrying. |

**What the server tells your assistant:**

> Manage the paid-media optimizer for the active brand (the budget-reallocation engine over Meta ad sets). action='create_portfolio' opens a portfolio (brand_id, ad_account_id, config: name/objective/level/mode/apply_mode/daily_total); 'create_from_suggestion' runs the onboarding flow — create + enroll — from a suggestion returned by optimizer_query action='suggestions'; 'enroll_adsets' enrolls ad sets (adset_ids) OR a whole campaign's ad sets (campaign_id — e.g. right after converting a CBO campaign) and queues the first cycle; 'convert_cbo' converts a CBO (campaign-budget) campaign to ad-set budgets so the optimizer can manage it — TWO-PHASE: mode='preview' (default) returns the computed per-ad-set budgets plus a confirm_token and writes nothing to Meta; mode='apply' with that confirm_token performs the real write; 'set_recommendation_status' approves/rejects ONE engine recommendation (portfolio_id + recommendation_id; the pending row IS the preview, so there is no confirm step — instead the write is refused if the row already moved out of expected_status, and re-approving returns the same receipt). Approving a fatigue rec opens a renewal task, whose id comes back in the receipt; 'set_recommendation_statuses' approves/rejects many at once and returns an ITEMIZED \{applied[], skipped[\{id,reason\}]\} — a bad or stale id is skipped, never hidden behind a count; 'set_renewal_task_status' closes a renewal work item (open\|done\|dismissed) with the same stale-state precondition; 'update_portfolio' edits portfolio settings (apply_mode='autopilot' is refused here — arming autonomous budget writes is a dashboard act); 'archive_portfolio' stops future optimization cycles (it does NOT pause any ad); 'unenroll_adsets' removes ad sets; 'run_now' triggers a reallocation cycle immediately for one portfolio_id (refused on an armed autopilot portfolio, whose cycle would write real Meta budgets; returns service_unreachable if the optimizer service is offline — the cycle still runs on its schedule). This tool does not pause or activate ads, ad sets or campaigns. Pausing is paid_manage action=update_entity (status PAUSED), preview → confirm, so the user confirms every pause; activating there also needs an admin's mcp_approval_grant. Use optimizer_query to read portfolios, performance, suggestions, and outcomes. Returns a structured needs_* result if a prerequisite (brand/role/integration) is missing.
