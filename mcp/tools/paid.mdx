### `paid_manage`

Reads your campaign structure; creates paused campaigns, ad sets, and ads; updates or pauses them; builds audiences and lookalikes; and keeps an audit log of every write.

**Good to know:**

- Every write is two-phase: `params.mode: "preview"` returns a diff and a `confirm_token` that lasts 10 minutes; repeat the call with `params.mode: "confirm"` and the token.
- Campaigns, ad sets, ads, and copies are created paused. Activating one, raising a budget past the brand's limit (by default, more than 30%), or any write on a brand with an approval chain returns `APPROVAL_REQUIRED` until an Admin or Owner calls `mcp_approval_grant`.
- `batch` previews many writes under one token.
- Each write receipt includes `undo`: the call that reverses it, or null with the reason it can’t be undone.
- `google_ads` runs one Google Ads operation (`update_campaign_budget`, `set_status`, `create_campaign`, `create_ad_group`, or `add_keywords`) with the same preview and confirm steps, and needs the brand’s Google connection. `ENABLED` needs an Admin or Owner.
- Boosting organic posts isn’t supported.

| --- | --- |
| Changes things | Yes |
| Listed in your assistant | Always. |
| Role | Viewer or higher for `hierarchy` and `activity`. Operator or higher for writes. Admin or Owner to set `guardrails`. Activating an ad, or raising a budget past the brand's limit, needs an Admin or Owner's approval. |
| Needs | An active brand. Connection: The one for what you act on: Meta (Facebook), Google. |
| Confirmation | Writes preview first and return a `confirm_token` with `expires_at`. Confirm with that token after the person says yes. |
| Completion | Returns the result in the same call. |
| Retry | Each `confirm_token` works once. Preview again to retry. |
| Rate limit | 60 calls per 1 hour per brand. See [Limits](/mcp/reference#limits). |

**Errors and statuses:**

| Code | When |
| --- | --- |
| `APPROVAL_REQUIRED` | Activating, a budget raise over the brand's spend limits (default +30%) or an approval-chain brand: an admin calls `mcp_approval_grant` with the `confirm_token`, then retry mode='confirm'. |
| `CONFIRMATION_REQUIRED` | Write actions are two-phase: call with params.mode='preview' to get a `confirm_token`, then params.mode='confirm' with that token. |
| `VALIDATION_ERROR` | params is the chosen action's own input. objective must be valid for the platform (e.g. `OUTCOME_*` for `meta_ads`). |
| `CONFLICT` | The item changed or is busy. Read it again, then retry with the current state. |
| `INTEGRATION_DISCONNECTED` | The connection lapsed. Reconnect it with `integrations_connect`. |
| `INTERNAL` | Something went wrong on our side. Retry once, then contact support. |
| `NOT_FOUND` | The item doesn't exist, or this brand can't see it. |
| `UPSTREAM_ERROR` | A platform or provider returned an error. `details` carries its message. |
| `needs_brand` | No brand is active. Call `brands_select`. |
| `needs_role` | The person's role is too low for this call. Viewer or higher for `hierarchy` and `activity`. Operator or higher for writes. Admin or Owner to set `guardrails`. Activating an ad, or raising a budget past the brand's limit, needs an Admin or Owner's approval. Ask an Admin or Owner. |
| `needs_integration` | The brand lacks the connection this call needs. Call `integrations_connect` with the `platform` the result names. |
| `RATE_LIMITED` | Wait `details.retry_after_seconds`, then retry. |
